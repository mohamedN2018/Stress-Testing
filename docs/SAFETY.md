# الأمان والاستخدام المسؤول — Sentinel Test Lab

Sentinel Test Lab أداة **لاختبار مشاريعك أنت فقط**. لا تحتوي أي وظيفة هجومية، وكل ما فيها مصمَّم
ليمنع استخدامها ضد طرف لم يصرّح بذلك.

## 1. ما الذي لا يفعله التطبيق (بالتصميم)

- لا يولّد حملاً غير محدود، ولا يوزّع الحمل على أجهزة أو proxies، ولا يزيّف عناوين المصدر.
- لا يحاول تجاوز rate limiting أو WAF أو CAPTCHA.
- لا يخمّن كلمات مرور ولا يستخدم قوائم كلمات مرور ولا يسجّل الدخول بحسابات حقيقية.
- لا يستغل ثغرات، ولا يستخرج بيانات، ولا يعدّل سجلات.
- لا يتابع إعادة التوجيه (redirects) حتى لا يخرج الاختبار إلى موقع آخر.
- لا يمر عبر proxy النظام، ولا يرسل أي بيانات إلى جهة خارجية.

## 2. محرك الأمان (`core/safety_manager.py`)

كل تشغيل يمر عبر بوابة واحدة: `SafetyManager.authorize_run`. إن رفضت، لا يُرسَل أي طلب.

| القاعدة | التفاصيل |
|---|---|
| قائمة أهداف مصرّح بها | لا يعمل أي اختبار إلا على هدف محفوظ مع إقرار تصريح مكتوب |
| تأكيد لكل تشغيل | خانة التأكيد تُلغى تلقائياً بعد كل تشغيل |
| النطاق | المسارات وطرق HTTP المسموحة تُحدَّد عند التصريح، وتُفحص لكل طلب |
| العناوين الخاصة/المحلية | مرفوضة إلا بتصريح صريح منفصل |
| إعادة فحص DNS | قبل كل تشغيل؛ إن تغيّر نوع الشبكة (عام ↔ خاص) يُلغى التشغيل |
| اختبار واحد في المرة | لا يمكن تشغيل اختبارين معاً |
| لا قيم غير محدودة | المعدل والمدة والمستخدمون يجب أن تكون أرقاماً موجبة محدودة |

### الحدود

| | الافتراضي (لكل الأهداف) | المرفوع (أهداف موثوقة فقط) | السقف المطلق (في الكود) |
|---|---|---|---|
| مستخدمون متزامنون | 5 | حتى 50 افتراضياً | 200 |
| المدة | 60 ث | حتى 300 ث | 900 ث |
| المعدل | 5 طلب/ث | حتى 50 طلب/ث | 200 طلب/ث |
| ميزانية الطلبات | 300 | حتى 15,000 | 100,000 |

- **الهدف الموثوق** = هدف محلي (loopback) أو هدف تم توثيق ملكيته (ملف على الموقع أو سجل DNS TXT).
- الهدف العام غير الموثّق يبقى دائماً على الحدود الافتراضية حتى لو فُعّلت الحدود المرفوعة.
- أي تشغيل يتجاوز الافتراضي يطلب **كتابة اسم المضيف** للتأكيد.
- حدود إضافية ثابتة: تقييم Flood ≤ 30 ث و ≤ 50 طلب/ث؛ تقييم Brute Force ≤ 20 محاولة وبفاصل ≥ 0.5 ث؛
  الفحص النشط (ZAP) ≤ 300 ث.
- تقييمات Flood و Brute Force والفحص النشط متاحة **للأهداف الموثوقة فقط**.
- **فحص معالجة المدخلات** (XSS / SQL / Open Redirect) للأهداف الموثوقة فقط وباختيار صريح. يرسل قيماً
  غير ضارة عبر GET فقط (علامة عشوائية، علامة اقتباس واحدة، عنوان `.example` غير قابل للحل)، ولا يحاول
  استغلال ما يكتشفه، وحدّه 6 معاملات لكل تشغيل.
- **الترويسات المخصصة**: حتى 10 ترويسات، للمحرك الداخلي فقط. مرفوضة: `Host` و `User-Agent` وكل ترويسات
  `X-Forwarded-*` و `X-Real-IP` وما شابهها، لأنها قد تغيّر وجهة الطلب أو تخفي مصدره. القيم تبقى في
  الذاكرة فقط؛ يُحفظ في السجل والتقرير أسماء الترويسات لا قيمها.
- **مراقبة الحاوية**: قراءة فقط (`docker ps` و `docker stats`)، محلياً أو عبر `ssh` بمفتاحك دون كلمة مرور.
  اسم الحاوية واسم الخادم يُتحقق منهما قبل تنفيذ أي أمر.
- الأسرار المكتشفة في صفحات موقعك (مفاتيح، tokens) تُسجَّل مقنَّعة ولا تُنسخ كاملة إلى التقرير.
- الفحص النشط (ZAP) يتطلب إضافةً لذلك هدفاً نطاقه «كل صفحات الموقع» ويسمح بـ POST، لأن القياس الفعلي
  أظهر أن ZAP يفحص مسارات على مستوى الموقع ويرسل POST بصرف النظر عن الصفحة المحددة.

### أثناء التشغيل (`RunGuard`)

- محدِّد معدل عام مشترك بين كل المستخدمين الافتراضيين (بلا أي burst).
- ميزانية طلبات دقيقة: عند بلوغها لا يُرسَل أي طلب جديد.
- **إيقاف تلقائي** عند: ارتفاع نسبة الأخطاء، تجاوز p95 للعتبة، أو إخفاقات متتالية (الهدف غير مستقر).
- **إيقاف طارئ**: زر في صفحة الاختبار وزر عام أعلى النافذة. يُلغي الطلبات الجارية ويقتل أي
  عملية خارجية (Locust/k6) مع كل العمليات المتفرعة منها.
- مهلة قصوى إجبارية حتى لو تعطّل المحرك.

## 3. سجل التدقيق

كل تصريح، بدء، رفض، إيقاف، تغيير إعدادات، وتصدير تقرير يُسجَّل في:
- جدول `audit` في قاعدة البيانات (يُعرض في صفحة الإعدادات).
- الملف `logs/audit.jsonl` داخل مجلد البيانات.

## 4. الأسرار

مفتاح ZAP و token الخاص بـ Cloudflare يُحفظان في **Windows Credential Manager** فقط.
عند تشغيل ZAP تلقائياً من التطبيق يُولَّد له مفتاح عشوائي لكل جلسة (في الذاكرة فقط)، ويستمع على
`127.0.0.1` فقط، ويُغلق مع إغلاق التطبيق.
لا يوجد أي مفتاح أو كلمة مرور في الكود أو في قاعدة البيانات أو في التقارير.

## 5. مسؤوليتك

- اختبر فقط ما تملكه أو ما لديك تصريح كتابي باختباره. اختبار أنظمة الغير بلا تصريح مخالف للقانون في أغلب الدول.
- على الاستضافة المشتركة (مثل Hostinger) الحمل يؤثر على مواقع عملاء آخرين: التزم بالحدود الافتراضية
  وراجع شروط مزوّد الاستضافة قبل أي اختبار حمل.
- ابدأ دائماً ببيئة Staging أو محلية، وبأقل حمل، وفي وقت هادئ.
- نتيجة "لم تُرصد مشاكل" لا تعني أن الموقع آمن أو محصَّن ضد DDoS؛ التقييمات هنا سطحية وغير اقتحامية.
